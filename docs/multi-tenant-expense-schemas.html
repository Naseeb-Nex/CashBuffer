Maybe Finance GitHub ↗

Modern personal & household wealth management OS. Scalable multi-user household partitioning using UUIDs and a polymorphic double-entry ledger design.

Tenant Scope: family_id Database: PostgreSQL ORM: Ruby ActiveRecord PK Type: gen_random_uuid() Ledger: Polymorphic Entries

🛡️ Tenant Isolation Guarantee

All core resources (accounts, categories, budgets, merchants, tags) enforce non-nullable family_id foreign keys. Multiple users join a single family with roles (owner/member). No cross-family read is possible without explicit family key scoping.

⚡ Scalability & High Throughput

Separates polymorphic transaction lines (entries) from rich metadata (transactions). Uses precomputed balances daily snapshot tables with unique constraints (account_id, date) to calculate charts instantly without aggregating millions of rows.

🔑 Key Multi-Tenant Indices

  • index_accounts_on_family_id
  • index_budgets_on_family_id_and_dates
  • index_entries_on_account_id_and_date
  • index_merchants_on_family_id_and_name (partial)

-- Maybe Finance: Scalable Multi-Tenant PostgreSQL DDL
-- Tenancy model: Household / Family scoped (`family_id` partition key)

CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- Root Tenant Entity: Family / Household
CREATE TABLE families (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255),
    currency VARCHAR(3) DEFAULT 'USD' NOT NULL,
    locale VARCHAR(10) DEFAULT 'en' NOT NULL,
    stripe_customer_id VARCHAR(255),
    date_format VARCHAR(20) DEFAULT '%m-%d-%Y',
    country VARCHAR(10) DEFAULT 'US',
    timezone VARCHAR(50),
    data_enrichment_enabled BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Tenant Users (Members of a Family)
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id UUID NOT NULL REFERENCES families(id) ON DELETE CASCADE,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    email VARCHAR(255) NOT NULL,
    password_digest VARCHAR(255),
    role VARCHAR(50) DEFAULT 'member' NOT NULL,
    active BOOLEAN DEFAULT TRUE NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_users_family_id ON users(family_id);
CREATE UNIQUE INDEX idx_users_email ON users(email);

-- Financial Accounts (Scoped to Family)
CREATE TABLE accounts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id UUID NOT NULL REFERENCES families(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    subtype VARCHAR(50),
    accountable_type VARCHAR(100),
    accountable_id UUID,
    balance NUMERIC(19, 4) DEFAULT 0.0 NOT NULL,
    cash_balance NUMERIC(19, 4) DEFAULT 0.0 NOT NULL,
    currency VARCHAR(3) DEFAULT 'USD' NOT NULL,
    status VARCHAR(50) DEFAULT 'active' NOT NULL,
    locked_attributes JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_accounts_family_id ON accounts(family_id);
CREATE INDEX idx_accounts_family_status ON accounts(family_id, status);

-- Categories (Custom per family or default)
CREATE TABLE categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id UUID REFERENCES families(id) ON DELETE CASCADE,
    name VARCHAR(100) NOT NULL,
    color VARCHAR(20),
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_categories_family_id ON categories(family_id);

-- Budgets (Scoped per family & date range)
CREATE TABLE budgets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id UUID NOT NULL REFERENCES families(id) ON DELETE CASCADE,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    budgeted_spending NUMERIC(19, 4) DEFAULT 0.0,
    expected_income NUMERIC(19, 4) DEFAULT 0.0,
    currency VARCHAR(3) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_budgets_family_date ON budgets(family_id, start_date, end_date);

-- Budget Line Items
CREATE TABLE budget_categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    budget_id UUID NOT NULL REFERENCES budgets(id) ON DELETE CASCADE,
    category_id UUID NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    budgeted_spending NUMERIC(19, 4) NOT NULL,
    currency VARCHAR(3) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_budget_category UNIQUE (budget_id, category_id)
);

-- Payees / Merchants (Global + Family Overrides)
CREATE TABLE merchants (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    family_id UUID REFERENCES families(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    color VARCHAR(20),
    logo_url TEXT,
    website_url TEXT,
    type VARCHAR(50) NOT NULL DEFAULT 'Merchant',
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_merchants_family_id ON merchants(family_id);

-- Transactions Details (Category & Payee classification)
CREATE TABLE transactions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    category_id UUID REFERENCES categories(id) ON DELETE SET NULL,
    merchant_id UUID REFERENCES merchants(id) ON DELETE SET NULL,
    kind VARCHAR(50) DEFAULT 'standard' NOT NULL,
    locked_attributes JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_transactions_category ON transactions(category_id);
CREATE INDEX idx_transactions_merchant ON transactions(merchant_id);

-- Ledger Entries (Polymorphic core transaction table)
CREATE TABLE entries (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    account_id UUID NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    entryable_type VARCHAR(100),
    entryable_id UUID,
    amount NUMERIC(19, 4) NOT NULL,
    currency VARCHAR(3) NOT NULL,
    date DATE NOT NULL,
    name VARCHAR(255) NOT NULL,
    notes TEXT,
    excluded BOOLEAN DEFAULT FALSE,
    locked_attributes JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_entries_account_date ON entries(account_id, date DESC);
CREATE INDEX idx_entries_entryable ON entries(entryable_type, entryable_id);

-- Daily Balance Snapshots (For fast reporting & charting without aggregate recalculations)
CREATE TABLE balances (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    account_id UUID NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    date DATE NOT NULL,

    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_account_date UNIQUE (account_id, date)
);
CREATE INDEX idx_balances_account_date ON balances(account_id, date DESC);

Invoice Ninja (v5) GitHub ↗

High-volume enterprise B2B invoicing & expense management platform. Employs multi-company organization scoping with a dedicated tenant join table (company_user) with JSON permission matrices.

Tenant Scope: company_id Database: MySQL / PostgreSQL Framework: Laravel 10 Pattern: Organization Multi-Tenancy Features: Soft Deletes, Multi-Currency, Granular Roles

🏢 B2B Organization Tenancy

Global users and accounts can belong to multiple companies. Each company has isolated expenses, vendors, clients, invoices, and expense categories. Access is regulated via company_user.permissions.

⚡ Scalability & Partitioning

All core tables include company_id as an indexed leading column. Composite indices on (company_id, is_deleted, expense_date) prevent full-table scans and make sharding or database partition by company seamless.

🔑 Key Multi-Tenant Indices

  • idx_expenses_company_date (company_id, expense_date)
  • idx_expenses_company_deleted (company_id, is_deleted)
  • idx_company_user (company_id, user_id) UNIQUE
  • idx_vendors_company (company_id, is_deleted)

-- Invoice Ninja: Enterprise Multi-Company Multi-Tenant DDL
-- Tenancy model: Organization scoped (`company_id` partition key with composite indices)

CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- Top-Level Billing & Subscription Account
CREATE TABLE accounts (
    id BIGSERIAL PRIMARY KEY,
    plan VARCHAR(50) DEFAULT 'enterprise',
    plan_term VARCHAR(20) DEFAULT 'month',
    plan_started DATE,
    plan_expires DATE,
    default_company_id BIGINT,
    num_users INT DEFAULT 1,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Tenant Isolation Root: Company / Organization
CREATE TABLE companies (
    id BIGSERIAL PRIMARY KEY,
    account_id BIGINT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    company_key VARCHAR(100) UNIQUE NOT NULL,
    industry_id INT,
    logo TEXT,
    settings JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_companies_account ON companies(account_id);

-- System Users (Cross-company identity)
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    account_id BIGINT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    first_name VARCHAR(100),
    last_name VARCHAR(100),
    email VARCHAR(255) NOT NULL,
    password VARCHAR(255),
    is_admin BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_account ON users(account_id);

-- Tenant Membership & Granular Access Control
CREATE TABLE company_user (
    id BIGSERIAL PRIMARY KEY,
    company_id BIGINT NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    account_id BIGINT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    permissions JSONB DEFAULT '{}'::jsonb,
    notifications JSONB DEFAULT '{}'::jsonb,
    settings JSONB DEFAULT '{}'::jsonb,
    is_admin BOOLEAN DEFAULT FALSE,
    is_owner BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_company_user UNIQUE (company_id, user_id)
);
CREATE INDEX idx_company_user_user ON company_user(user_id);
CREATE INDEX idx_company_user_company ON company_user(company_id);

    is_deleted BOOLEAN DEFAULT FALSE,

CREATE INDEX idx_expense_categories_company ON expense_categories(company_id, is_deleted);

Ghostfolio GitHub ↗

Privacy-first wealth, expense & portfolio tracking software. Implements composite primary & foreign key constraints ([id, userId]) at the database layer to mathematically guarantee zero data leaks across tenants.

Tenant Scope: Composite [id, userId] Database: PostgreSQL ORM: Prisma Backend: NestJS / TypeScript Security: Foreign Key Compound Enforcement

🔒 Compound Foreign Key Guarantees

Instead of relying merely on application-level where: { userId } clauses, the database schema itself declares Account PRIMARY KEY (id, userId) and child tables reference FOREIGN KEY (accountId, userId). A query cannot accidentally join records belonging to another tenant.

🤝 Fine-Grained Tenant Delegation

Through the Access table, a user can grant scoped read/admin access to another tenant (granteeUserId) with expirations and specific scope arrays without sharing passwords or combining database rows.

🔑 Key Multi-Tenant Indices

  • Account PRIMARY KEY (id, userId)
  • AccountBalance UNIQUE (accountId, userId, date)
  • Order INDEX (accountId, userId)
  • Access INDEX (userId, granteeUserId)

/// A stock split of an asset profile. The numerator is the number of shares
/// held after the split, the denominator the number of shares held before, for
/// example 4 and 1 for a 4:1 split or 1 and 10 for a 1:10 reverse split.
///
/// The ratio is stored as two integers instead of the resulting factor, so that
/// it stays exact, for example 1/3 for a 1:3 reverse split.
///
/// Activities before the date are adjusted by the ratio: the quantity is
/// multiplied by it and the unit price divided by it, so that the total value
/// of an activity stays the same.
///
/// Market data is already split-adjusted by the data providers and must not be
/// adjusted again.
model AssetProfileSplit {
  createdAt       DateTime      @default(now())
  date            DateTime
  denominator     Int
  id              String        @id @default(uuid())
  numerator       Int
  symbolProfile   SymbolProfile @relation(fields: [symbolProfileId], onDelete: Cascade, references: [id])
  symbolProfileId String
  updatedAt       DateTime      @updatedAt

  @@unique([symbolProfileId, date])
  @@index([date])
}

Comparison of multi-tenant strategies across open-source expense systems to determine best architectural fit.

Dimension Maybe Finance Invoice Ninja Ghostfolio Supabase / Postgres RLS (Best Practice)
Tenancy Boundary family_id (Group/Household) company_id (Enterprise Org) userId with composite PKs tenant_id via auth.jwt()
Isolation Enforcement Application/ORM scope query filters Application Query Scopes + Company Middleware Database Foreign Key constraints (compound) Kernel-level Postgres Row Level Security (RLS)
Multi-User Membership users.family_id (1 user = 1 family) company_user M:N table + JSON permissions Access delegation table for sharing tenant_members table with role enum
Expense / Transaction Model Polymorphic entries (ledger line) + transactions Direct expenses table with vendor & client links General Order activity table (Buy/Sell/Item/Fee) Double-entry ledger (transactions + postings)
Reporting Performance Precalculated daily balances snapshot table Composite index queries on (company_id, expense_date) AccountBalance unique daily snapshots Materialized views / daily snapshot tables
Horizontal Scalability (Sharding) High (Shard database by family_id) Very High (Shard database by company_id) Medium (Composite keys assist Citus / PG partitioning) Very High (Partition table by LIST / HASH on tenant_id)
Accidental Leak Vulnerability Medium (Depends on developer writing where(family_id)) Low-Medium (Uses global Laravel scopes) Zero for joins (DB rejects mismatched accountId, userId) Zero (Enforced at SQL engine level on every connection)
